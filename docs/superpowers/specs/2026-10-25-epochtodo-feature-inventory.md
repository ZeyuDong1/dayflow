## 一、任务系统

- 任务树（任意嵌套层级的父子任务）
  - 同级排序：bang 优先级降序 → sort_order 升序 → created_at 升序
  - 孤儿任务提升为根（父删除/归档时）
  - ⚠️ 冲突：Dayflow 已有的"任务"（`task_activities` 手动计时工作段）
    - 〔用户决定〕**Dayflow 的"任务"定义改称"类型"**，"任务"一词在合并后专指 EpochToDo 任务树；两概念并存为两个实体，`task_activities` 行为原样保留
- 任务状态机：queued / waiting / active / archived
  - 专注结算回 queued；等待挂起进 waiting；完成归档整棵子树（深度上限 20）
  - 计时到期**不改**状态（供横幅/Nag 复用）
- 任务类型：standard（标准）/ reminder（软提醒、家务倒计时）/ training（训练）/ notification（AI 硬提醒）
- 创建去重：同名未归档任务直接复用（training 除外）
- 任务字段：标题、多行备注（追加式）、估计时长、累计专注时长、标签、项目、父任务
  - 累计专注时长逐层累加到所有祖先
- next_action 标记（队列/建议列表的筛选条件）
- Bang 优先级（标题任意位置 `!` 计数，`!!`/`!!!` 更高）
  - subtree-max 聚合：父任务取自身与子树最大值（只向上传播，父的 `!!` 不抬子）
  - 用于任务树/队列/Spotlight 建议排序；Overlay 队列槽位例外（只看任务自身）
- 副焦点（◎，最多 2 个）
  - 主/副焦点互斥；切换焦点自动轮换（最近专注过的副焦点优先晋升，其次最早打旗）
  - archived/active 状态的带旗任务不占额度
- 完成任务
  - 归档自身+全部未归档后代（BFS，深度上限 20 防环）
  - 焦点转移：正在专注且有父 → 转到父任务并继续专注；无父 → 停止专注
  - 无项目的 standard 任务必须先选项目才能完成（三入口：任务页 Complete、Spotlight `#` 模式、Reminder 窗）
  - ⚠️ 冲突：任务"项目"与 Dayflow 项目树（改名后为**类型树**）
    - 〔用户决定〕**两者是两码事、互相独立**——任务项目是独立的简单列表（名称/颜色），不并入类型树、不共享数据
    - 项目管理轻量化（建造者决定）：完成选择器可内联新建项目；任务页提供简单管理（改名/换色/删除），不做 EpochToDo 式三列看板
- 删除任务：递归删除整棵子树；mdSync 联动删除 MD 行（先删行再删库）
- 空白标题草稿清理（Spotlight 关闭时自动删除）
- 拖拽调整层级/排序（Spotlight 任务树）
- 备注追加（`>` 命令、子任务 `Context: …` 自动写入）

## 二、计时系统

- Focus 专注秒表（全局同时只开一个）
  - 每任务至多一行 timer；开始新专注自动结算当前专注（防丢时长）
  - 其他非 training 的 active 任务被"排他清场"降级回队列
  - 结算门槛 3 分钟：<3min 丢弃不记账；≥3min 记入累计时长 + 写历史 + 祖先累加
  - ⚠️ 冲突：与 Dayflow 自动活动追踪（2s 窗口轮询 → 活动段 → 归类）
    - 〔用户决定〕**两者都按其原始设计工作，互不交叉**——专注会话不混入活动段归类，活动段也不改写专注会话；呈现合并见第十一节
- Wait 等待倒计时（挂起当前工作，可多任务并行挂多个）
  - Suspend & Resume：`@25m` 一键挂起当前、切换到新任务
  - 到期不删倒计时行、不改状态（横幅/Nag 复用）
- Ad-hoc / reminder 任务倒计时（家务等，默认 30 分钟）
  - 取消即整个任务删除（reminder/training 专属语义；有 GPU 先释放）
- Training 训练计时
  - 按 GPU 串行（GPU 被占自动暂停旧任务）、跨 GPU 并行
  - 暂停：释放 GPU、回队列；停止：分"已完成/未完成"两分支
  - 完成自动生成跟进任务（`Process …` / `📋 Check results: …`）
- 到期分流
  - 软路径（reminder 类）：只出横幅/卡片，不弹窗、不发声
  - 硬路径（standard/training/notification）：弹 Reminder 窗 + 系统通知（静音）
  - ⚠️ 冲突：与学习监督强打断面板（InterruptOverlay）
    - 〔用户决定〕**独立共存，不统一通道**——Dayflow 监督是阻止用户玩乐的强打断，EpochToDo Reminder 是给用户的重要提醒，职责不同、各走各的
- Nagging 追命提醒：逾期后每 15 分钟重放一次提醒（间隔可配置）
- Snooze 贪睡：+5 分钟通用（含 ADHOC/standard）；training 到期 Esc = 负时 15 分钟（可选 5/30）
- Quick Countdown Picker 快速倒计时：5m/15m/25m/45m/1h/2h 预设 + 自定义 + 剩余显示 + 一键取消
- 右键菜单：重置倒计时/取消倒计时/完成；支持 `30m/1h/45s` 时间输入
- 崩溃恢复与启动对账
  - 重启恢复进行中的计时；僵尸 active 训练任务 3 分钟对账归档；GPU 空闲状态修复

## 三、Spotlight 全局命令栏（Alt+Space）

- 全局热键呼出/收起（热键可改，改动即时重注册），居中到光标所在显示器
- 命令文法（前缀式）
  - `>备注` 追加备注到当前专注任务
  - `+标题@时间` 创建软提醒（缺省 30 分钟）
  - `%标题` 创建训练任务（`` `GPU名` `` 指定 GPU）
  - `#查询` 搜索并完成任务
  - `!标题` 创建/切换专注
  - `标题`（无前缀）创建任务入队；带时间自动升级为软提醒
  - `@25m` 单独成句 = 挂起当前（SUSPEND）
  - 时间表达式 `@90m / @1h / @45s`（缺省单位 = 分钟）
  - 子任务语法 `主标题 : 父任务搜索词`（有专注任务时为"同级"语义：父=当前任务或其父）
  - 项目 `$项目名`（任务自己的项目列表）；GPU `` `GPU名` ``（CREATE/FOCUS 带 GPU 自动升级 TRAINING）
- 任务树面板
  - Tab / Shift+Tab 缩进/反缩进（保持输入焦点，可连续打字）
  - 右键菜单（重置/取消/完成）、◎ 副焦点开关、内联倒计时面板（Quick Countdown Picker）
  - 训练/GPU 监控任务从普通任务树隐藏（decluttering）
- 建议列表
  - bang 优先级稳定排序；空输入显示 next_action 队列前 10
  - ↑↓ 循环高亮、Ctrl+1..9 直选、Enter 执行、Esc 关闭、点击 = 专注
- 软提醒横幅（过期 reminder）：重新设定（+5/+20/+40 或 `30m/1h/45s`）/开始专注/完成
- AI 提醒卡片行（转软提醒/完成/忽略按钮）
- 完成确认弹窗（无项目任务强制先选项目，↑↓/Ctrl+数字选择，可内联新建）
- 训练任务创建的 GPU 选择模式（显示占用标记）
- ⚠️ 冲突：无——Dayflow 无对应物，纯新增

## 四、悬浮 Overlay（置顶透明窗）

- 当前主焦点标题（呼吸光晕 + 长标题跑马灯）
- 副焦点行（最多 2 个，紧挨主焦点下方）
- 队列 3 槽位（按任务自身 bang 数排序，不做父子聚合）
- 等待倒计时显示
- 训练卡：最近 3 个训练 + 预计结束时间
- AI 软提醒卡行（info/progress/failure 非阻塞青色卡片）
- 动效配置：光晕与跑马灯各自独立的开关/强度/速度滑杆（设置页实时预览）
- 窗口行为
  - 点击穿透切换（IPC 控制）
  - 多显示器 bounds 校验（防拔显示器后错误尺寸被记忆）
  - 尺寸/位置记忆（1s 防抖保存 + 启动 5s 宽限期不保存）
  - 置顶每 30 秒重申；托盘"Re-assert Overlay Topmost"手动补救
- ⚠️ 冲突：与学习监督强打断浮层（InterruptOverlay）
  - 〔用户决定〕**共存**——职责不同（被动展示 vs 强打断），互不替代

## 五、Reminder 弹窗（硬提醒）

- 弹窗 + 提示音 + 任务栏闪烁 + 全桌面置顶
- Enter = 完成（training 走停止流程、无项目 standard 先选项目、通知类仅关闭）
- Esc = 关闭（training = 负时 15 分钟，可选 5/30）
- Snooze 默认 5 分钟（training 负时除外）
- ⚠️ 冲突：与学习监督强打断面板
  - 〔用户决定〕**不重叠，独立共存**——Dayflow 监督用于阻止用户玩乐（强打断），EpochToDo Reminder 是给用户的重要提醒，两者各司其职

## 六、AI 软提醒与 Webhook（127.0.0.1:62222）

- `POST /hook` 外部集成协议（工具/agent 统一入口）
  - `kind:"ai"` 软提醒：status `success/needs_input/review` → 硬弹窗 + `🤖 来源 · 标题` 持久任务；`failure/progress/info` → 临时卡片（不落库）
  - `kind:"ai-dismiss"` 撤回：按来源/标题精确匹配删除 `🤖` 任务（递归删子树）；force 控制渲染端是否连 needs_input/review 行动卡一起清
  - 通用通知 `{title, message}` → 硬弹窗
  - 训练状态更新（`task_id/gpu_name/eta/metrics`）→ 训练任务/GPU 卡
  - UTF-8 整包解码（防多字节跨包乱码）
- `🤖` 提醒任务：标题带来源，备注含详情/链接；"转为软提醒"=插入过期倒计时进横幅
- AI 卡片管理
  - 各窗口独立卡片行（上限 20，新→旧）；状态色标（✓/✕/!/?/⋯/i）
  - 跨窗口即时同步；卡片动作（转软提醒/完成/忽略）
- 桌面宠物桥
  - `GET /bridge/state`（桥状态）、`GET /bridge/reminders`（拉取未播报提醒，announced 去重）
  - `POST /bridge/tasks`（桥建任务）
- opencode 插件自动上报（session.idle）+ `notify_agent.sh` 手动脚本
- ⚠️ 冲突：与 Dayflow AI 通道（ai-memory 侧车、导师 Agent）
  - 〔用户决定〕**不冲突，各走各的**——epochtodo 通道传的是**外部 agent** 经 hook 递来的固定消息（如 hermes 触发"GPU 空闲"通知），Dayflow 是内部 AI；语义无需统一
- ⚠️ 冲突：外部协议是硬约束（payload 形状不可改）——与"重实现自由"抵触处以协议为准（约束 §3.4）

## 七、mdSync 双向同步

- `epochtodo.md` checkbox bullet 格式（`- [ ]`，缩进 = 层级；Obsidian/VS Code/记事本皆可编辑）
- 笔记 → 应用
  - 新 bullet = 新任务；改行 = 改名；勾选 = 删除任务；删行 = 删除任务（内容 hash 匹配）
  - 防抖 2 秒 + 3 秒 mtime 轮询兜底（抗 Windows 原子保存）
- 应用 → 笔记
  - 新任务插入父子弹群末尾；改名就地重写该行；完成打 `[x]`
  - 层级变更 = 子树手术式搬移（保留注记行相对缩进）；防抖 0.5 秒
  - `[x]` 行永不删除（用户自行清理）
- 双向冲突规则：MD 侧改名获胜（DB 跟随修复）；watcher 同步只 MD→DB 单向不回写（保护用户编辑）
- 启动修复：僵尸 active、缺失 next_action 自动纠偏
- 导入（含查重/强制导入）、导出、按文件夹启用
- ⚠️ 冲突：无——Dayflow 无对应功能；与 Ctrl+E 报告导出不同层次，共存

## 八、wandb / GPU 训练监控

- wandb 自动发现（GraphQL 轮询 30s，最近 5 项目，running run 过滤）
- GPU 卡：配置名、ETA、epoch/iter 进度、hostname、GPU 型号、wandb 链接
- 训练任务自动创建/绑定 GPU；正常结束自动归档 + 删卡
  - crashed/killed 不归档不删卡，转停滞提醒
- webhook 训练更新 + 去重（任一 wandb 条目在跑时整体压制 webhook 通道）
- GPU 健康检查（每 60 秒）
  - 停滞告警：默认 5 分钟无更新判停滞，每 10 分钟重提醒（弹硬窗）
  - GPU 空闲告警：有排队训练任务时空闲 GPU 提醒（15 分钟节流）
  - 静默时段默认 23:00–8:00（整检查暂停，环绕区间支持）
- 启动清理：wandb 幽灵卡/孤儿 webhook 任务清理
- ⚠️ 冲突：无——Dayflow 无 GPU 概念，纯新增
- 界面归属（建造者决定）：GPU 卡面板挂新"任务"页侧栏（+新建、拖入分配、webhook 卡禁拖），不设独立 Dashboard

## 九、时间轴扩展：任务条与合规比例（〔用户决定〕新方案，替代 EpochToDo 独立时间轴）

- EpochToDo 的"专注会话史"独立视图**不做**；专注会话**归并到 Dayflow 时间轴**呈现
- 任务占用窄条：现有时间轴右侧紧贴一条**比较窄的竖条**，代表任务占用时间
  - 每个专注会话一个色块，高度按时长比例，颜色=任务项目色
  - **条上不显示文字等信息**（保持窄、省空间）；**点击色块 → 显示详情**（任务名、起止时间、时长、合规比例、证据摘要）
- 合规比例（结合 AI 截图分析）
  - 对每个专注会话，取会话区间内的截图样本（复用 Dayflow 截图管线），判定"用户是否在执行该任务"，合规比例 = 在做该任务的样本 / 总样本
  - 例：用户设定 2 小时专注某任务，全程在做 → 100%
  - 呈现：色块内以填充/色深映射比例（不在条上写字），详情里给数字与证据
  - 无截图样本（未开截图/会话过短）→ 不显示比例，仅显示占用
  - 分析结果缓存入库（一次分析不重复花 LLM）；惰性触发（打开时间轴/当日分析时），节流防抖
  - 〔建造者决定〕分析复用现有 AI provider 管线（providers.ts），逐会话批量送样判定 on/off-task；阈值与抽样密度在实施计划中定
- 与活动段的关系：互不交叉（见第二节裁决）——窄条只反映专注会话，不改写活动段数据
